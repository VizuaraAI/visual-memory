# Where Does the Picture Live in a Hybrid Mamba Model?

The recurrent state of a hybrid vision-language model relays the picture
rather than storing it. This repository contains every instrument, experiment,
figure, and paper source behind that finding.

**Read the story:** [visualmemory.vercel.app](https://visualmemory.vercel.app)
(interactive article with animated figures and a 9-minute film) ·
[extended paper (PDF)](https://visualmemory.vercel.app/assets/paper-extended.pdf) ·
[conference version (PDF)](https://visualmemory.vercel.app/assets/paper-conference.pdf)

## The question

A hybrid model carries two kinds of memory. Its attention layers keep a
growing cache: every token, including every patch of an image, stays there.
Its Mamba2 recurrent layers keep a single fixed-size state that every new
token partially overwrites. In Zamba2-VL-7B, all 81 decoder layers carry a
recurrent state and only 13 also carry attention. While the conversation
drifts away from an image, where does the picture live?

## The findings

1. **The state records gist, not particulars.** Right after an image, a linear
   probe reads which object was shown at 92.5% from the best single layer
   (chance 12.5%), while count and position barely clear chance.
2. **The forgetting schedule is computable from the weights.** Each of the
   9,072 heads has a half-life, ln 2 / (|A| Δ̄), with nothing fitted. The
   median is 6.6 tokens (2.9 and 2.6 at two smaller scales).
3. **What a probe reads at distance is mostly not memory.** With write
   strength held fixed, fast heads (2.3-token half-life) still decode the
   object at 26.6% sixty-four tokens later, where their own parameters retain
   4e-9 of the trace. Deleting attention's copy of the image, without touching
   any recurrent state, collapses them to 7.8%, below chance. Deleting the
   same number of text entries instead raises the reading. The recurrent
   channel relays what attention holds; it does not store the picture.
4. **The model's own answers agree.** Swapping all 81 recurrent states between
   runs changes nothing (100/100 follow the run's own image); swapping 7 of 13
   attention caches flips 94/100 to the other image.
5. **The practical edge case for pruning.** Keeping a quarter of the visual
   key-value entries is free at every distance tested; below that, the cost
   grows with distance, roughly tripling by 512 tokens at 5% retention.

## Layout

```
lab/          instruments: telemetry, dynamics, probes, splice
analysis/     decoding and statistics
figures/      every figure; style.py holds the shared visual system
results/      raw JSON summaries (large .npz feature archives are not tracked)
paper/        LaTeX sources for the arXiv, ICLR, and NeurIPS versions
docs/         the website (deployed to visualmemory.vercel.app)
specs/        experiment specifications
modal_vlab.py Modal entrypoints that ran the GPU experiments
```

The instruments read layer counts, head counts, and state widths from each
loaded checkpoint's own configuration, which is what let the same code run at
three scales (7B, 2.7B, 1.2B) and on a second model family.

## Reproducing

Every number comes from a scripted experiment on public checkpoints
([Zamba2-VL-7B](https://huggingface.co/Zyphra/Zamba2-VL-7B), Apache-2.0, with
its 2.7B and 1.2B siblings) over COCO val2017 annotations. The GPU runs used
Modal H100s; total compute across the project was under $30. The large `.npz`
feature archives that some analysis scripts consume are regenerated by the
collection experiments in `modal_vlab.py`.

## A note on an earlier claim

An earlier draft reported that fast-decaying heads decode better than slow
ones at long distance (61.7% vs 16.7% at d=64). That reversal was an artifact
of write amplitude: the same gate that sets a head's decay also scales how
hard it writes. With write strength held fixed, the ordering follows decay.
The corrected story, which all current materials use, is that the ordering is
exactly as decay predicts and the amounts are far larger than decay permits.
